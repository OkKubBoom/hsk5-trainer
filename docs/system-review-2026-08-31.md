ครูสอนภาษาจีนอ้าง 8 คำตายตัวและ 13-17% ของคลัง ผู้แย้งรัน `selection.build_daily_drill(chin)` จริงได้ `mix={'due':0,'wrong':1,'new':14,'filler':25}` — เพราะทางเติมที่ `core/selection.py:249-262` ทำงานเมื่อยังไม่มีของค้าง **เชื่อผู้แย้ง**: 8 เป็นเพดานเฉพาะ steady state ไม่ใช่เพดานตายตัว และตัวเลข 384/287/213 มาจากสคริปต์ที่อยู่นอกโปรเจกต์ ทำซ้ำไม่ได้ ห้ามใช้ตัดสินใจ · **กลไกที่ทั้งคู่เห็นตรงกันและจริง**: `SRS_BACKLOG_CEILING=130` (`settings.py:135`) ตัดโควตาเหลือครึ่งที่ 91 และเหลือ 0 ที่ 130 โดยผู้เรียน**ไม่มีทางรู้ว่าถูกเบรก** → งานที่ควรทำจริงคือบรรทัดเดียวบนหน้า "วันนี้" ว่า *"วันนี้ไม่มีคำใหม่ เพราะของค้าง X ใบ"* (ข้อมูลอยู่ใน `today_summary` แล้วที่ `selection.py:303`) แล้วค่อยเขียนสคริปต์จำลองลง repo ก่อนคิดจะแตะสูตร

**B. mock หนักกว่าของจริงกี่เท่า — 2.7 / 1.9 / 3.3**
ผู้รู้รูปแบบข้อสอบอ้าง 2.7 เท่า (11,175 vs 4,101) ผู้แย้งวัดซ้ำได้ 1.9 เท่า (12,089 vs 6,344 นับบทอ่าน+โจทย์) และ 3.3 เท่าถ้านับเฉพาะบทอ่าน **เชื่อผู้แย้ง** เพราะนับด้วยวิธีเดียวกันทั้งสองฝั่ง และตัวเลขต้นฉบับทำซ้ำไม่ได้ **ข้อสรุปไม่เปลี่ยน** — กลไก `rng.sample` รายข้อยืนยัน 100% และการกระจาย 15 ข้อไปอยู่ 12.9 บทคือของจริง ทำข้อ 2.1 ต่อได้ แค่ห้ามอ้างเลข 2.7

**C. การ์ดฟังเสียงถูกทดสอบเป็นการ์ดอ่าน — เป็นตัวเลขที่โกหกอยู่ตอนนี้ หรือบั๊กแฝง**
ครูอ้างว่าโกหกอยู่ตอนนี้ ผู้แย้งตรวจ group by learner: การ์ด audio 109 ใบเป็นของ **learner 1 (nong ซึ่งเป็นบัญชี seed จาก README)** เท่านั้น bam/chin มี recognize 2,206 ใบล้วน **เชื่อผู้แย้ง** → ลดเป็นบั๊กแฝงที่จะระเบิดตอนเปิดพาร์ทฟัง · **แต่สิ่งที่ค้นพบระหว่างทางสำคัญกว่า:** `seed_hsk5.py:190-192` สร้างการ์ดสองชนิด ส่วน `accounts.py:40` / `make_learner.py:63` สร้างชนิดเดียว = **ผู้เรียนสองมาตรฐานในระบบเดียว** ทดสอบด้วยบัญชี seed แล้วผลไม่ตรงกับผู้ใช้จริง เป็นกับดักที่ทำให้บั๊กหลุดผ่านเทสต์ — ให้ทั้งสามทางเรียกฟังก์ชันสร้างการ์ดตัวเดียวกัน (เล็ก)
